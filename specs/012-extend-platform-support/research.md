## Darwin ARM64 ABI: source findings and pending native probe

Scout reported a source-level ABI risk, not a runtime result. Apple's [XNU `fcntl.h`](https://github.com/apple-oss-distributions/xnu/blob/main/bsd/sys/fcntl.h) declares `open(const char *, int, ...)` and `fcntl(int, int, ...)`; creation mode and command-dependent third arguments are variadic. Apple's [Apple silicon architectural differences](https://developer.apple.com/documentation/apple-silicon/addressing-architectural-differences-in-your-macos-code) describes differences in ARM64 variadic argument passing. Consequently a fixed-argument P/Invoke declaration with a third argument cannot be presumed ABI-correct on Darwin ARM64 merely because it works on Linux. The header also defines Darwin flags; select values from the actual target SDK, not Linux constants. This is not proof that a particular binding fails or works.

Before T002 or T003 relies on any Darwin binding, run a bounded native Apple Silicon probe in a disposable workspace, recording macOS build, architecture, SDK/runtime, filesystem, exact source/commands and results. Exercise the **actual candidate interop path**, including creation with `O_CREAT` and mode, and any `fcntl` command with its actual third-argument type; compare observed 0600 permissions and duplicate/close-on-exec behavior to a compiler-built C reference using the SDK declarations. Demonstrate no-follow, same- and cross-process contention, explicit unlock with a live duplicate, and meaningful failure/errno handling. The test observer must detect a deliberately held duplicate. Do not commit a shim from this source finding; if a correct small binding cannot be demonstrated, return the design choice to Conductor. Source evidence alone is not a native pass.

Separately probe descriptor-anchored unlink and directory `fsync` on the candidate local filesystem, recording success or errno and verifying that injected sync failure remains incomplete. Directory sync support and durability semantics are unverified; a successful call or process restart is not proof of power-loss survival. T005 and affected Mac acceptance remain gated on actual native evidence.

Identify a repository-available native runner image with the pinned SDK, Playwright driver, both browsers and a usable shell. No changes to production, CI or owner state.

This gates the respective Darwin binding, observer and runner decisions, **not** Linux candidate generation or test design. The two `open` signatures in the existing Linux code are not evidence of Darwin calling convention correctness. If no small verified option exists, return to Conductor before introducing a native shim or other dependency.

### SC-002: what the F002 sources establish

- **Directory anchoring and accurate outcomes.** [FR-008–010](../002-shared-library-export-deletion/spec.md#requirements-mandatory) and the [outcome contract](../002-shared-library-export-deletion/contracts/http-api.md#preview-and-confirm) define what the researcher can rely on: unselected documents stay unchanged and each item is reported as deleted or not completed. [T013](../002-shared-library-export-deletion/evidence/t013-managed-originals.md#safety-verified) records Linux unlink/sync ordering, failure and retry checks. The [Linux operation](../../src/LexScholar.Infrastructure/DocumentStore.fs#L93-L110) uses the same directory handle for unlink and sync. T005 must exercise path replacement on the candidates; the historical record is not that test.
- **Managed reimport.** [T015](../002-shared-library-export-deletion/evidence/t015-reimport-safety.md#deterministic-boundaries-and-observations) records an app-mediated concurrent reimport getting a fresh document ID and storage key; processing the old item leaves the new bytes intact. Preserve that check on both targets.
- **Limit, not an exception.** The Linux operation addresses a directory entry by name; it does not compare the entry with the earlier file's identity. Neither T013's no-op retry *after completion* nor T015's fresh key proves protection against an external same-key substitution *before unlink inside the opened directory*. [Sage's scope](spec.md#edge-cases) adds no such guarantee and records no acceptance of that risk. No new identity scheme or task is called for.

**Settled by the owner:** record only the targets and versions actually verified. A runner label or a passing result on one OS version establishes neither a minimum nor a range. Later candidate evidence may add another verified configuration. **Risk acceptance remains with the owner:** the [restart-lock incident](../../docs/specification-index.md#deferred-scope-and-limits) was accepted for a different release; reappearance blocks passing evidence here. Scout's findings above are source-level only; no candidate, native pass or owner smoke is supplied by these planning artifacts.
