# F002 validation quickstart

After implementation only; this plan does not implement these routes. Use isolated temporary workspaces and public fixtures, never real research documents. Linux with Playwright Chromium and Firefox installed; `scripts/install-browsers.sh` if needed. Start with `dotnet run --project src/LexScholar.Server` using a temporary configured data directory. For every unsafe request obtain the token from `GET /api/antiforgery`, send `X-CSRF-TOKEN` and the local `Origin`. Contract examples are in [HTTP](contracts/http-api.md); ZIP fields in [format](contracts/export-format.md).

1. Import two fixture PDFs; leave one unassociated and associate the other to two projects with different roles. Generate or seed distinct valid stored summaries with page citations and context. Request export, save ZIP and inspect with standard ZIP/JSON tools. Verify every original's bytes, every role, summary, page reference and generated/unverified notice; inspect text files without running LexScholar. No credentials or settings should appear.
2. With controlled test handshakes, change association/role/summary during ZIP construction. Every successful export matches one complete pre- or post-change state, never a combination that did not exist. Missing, wrong-length or unreadable original, simulated read failure and disk-full construction yield error and no completed ZIP. Existing library and running summary are unaffected.
3. In both browsers select shared and unassociated documents, inspect Portuguese impact and cancel; confirm no data changed. Preview again, change an association or summary in a second tab, then confirm: refreshed impact requires another confirmation. Confirm a new preview and verify shared associations and each project's stored summary are removed, while unrelated documents remain.
4. Hold first-generation preparation, regeneration preparation, active jobs and late completion with deterministic fake-service/extraction handshakes. Confirm deletion, release held operations and verify no post-deletion admission, further send or stored summary. Test reimport vs pending deletion and failure outcomes; do not use timing sleeps.
5. Inject a process stop/failure before and after intent commit, metadata transaction, unlink and completed marker; restart against the same temporary workspace. Confirm per-item outcomes, idempotent recovery, no quarantine of pending deletions, and no false success on denied unlink or full disk. Mix successful and failed items; verify accurate partial results and unaffected unselected data. Simulate lost POST response; reconcile using the preselected operation UUID and list after restart.
6. Verify Host/Origin and antiforgery rejection, no network transmission during export/deletion, no sensitive content or storage paths in errors/logs. Test browser download interruption and private temp cleanup, including restart cleanup.

When task IDs exist, use `scripts/check.sh <task IDs>` at RED/GREEN and before PRs; CI runs the full suite. Record storage/startup/security race evidence and manual Firefox/Chromium observations per AGENTS.md. No automated suite is run for planning-only changes.
