**Outcome: the assumption holds with the registry design.** A configured-service summary runs detached from the request, survives a document switch and a project switch, and is found on return. The stop-and-re-plan gate did not trigger.

- **RED** (`d11a072`): `scripts/check.sh T002` — 53 tests, 17 failed. The browser journey for the document switch first failed at a test-helper step (it did not wait for the first "Add as Focused Source" to finish before importing the second PDF); fixed in the same commit before GREEN.
- **GREEN** (`b0bbc30`): `scripts/check.sh T002` — 53 tests, 0 failed, 0 skipped: the three contract tests (202 while the fake holds its answer; closing the POST connection does not fire `Cancelled`, then `GET` returns the finished summary with its citations; no state for an unknown pair), six `SummaryJobsTests`, four client state tests, and the journeys in Chromium and Firefox (ask on A, open B, release, open A: summary and a working citation; the same with a project switch).
- **Regression**: `scripts/check.sh T001 T002 T003 T004 T005 T006 T007 T008 T010 T011 T013` — 443 tests, 0 failed, 0 skipped (these ids also select the F003 and F005 tests that share them).
- **Existing tests changed**: F003's configured-path tests in `SummaryContractTests.fs` and `SummaryReferenceSetTests.fs`, and two in `ChatGptContractTests.fs`, now read `202` + `GET` through `settledState`/`asEvent` (same assertions on checks, citations and failures). The two "abandoning the request cancels the service call" tests contradict FR-001 and became "closing the request does not stop the summary". F003's progress-event assertions on the 40-page document were dropped for the configured path (progress is T004, which re-adds them against `GET`).

Tying it to `RequestAborted` alone did not fail them, because Kestrel does not abort a request that completed normally; the design never uses it, and the `202`-before-answer and `Cancelled` assertions guard the streamed-response design.
- **Limitations**: the plan path still streams until T003, so the sign-out reach into background jobs is unproven here. Progress is not reported (T004). Finished and failed jobs are in memory only (T006). `DELETE` and `GET /api/summaries` are still 501. Tests wait with handshakes (`SummaryJobsAccess.settled`), but a journey that returns while the job is still running waits for the client's 2 s poll. Full suite: CI on the PR.
