# Tasks: F004 — Background Summaries

**Feature**: F004 | **Inputs**: [spec](spec.md), [plan](plan.md), [research](research.md), [data model](data-model.md), [contract](contracts/summary-api.yaml), [quickstart](quickstart.md)

Each task is one vertical slice and one PR: tests first (meaningful RED, then GREEN), tagged `Trait("Task", "Txxx")`, run with `scripts/check.sh Txxx`. Design decisions are in `research.md` (§n below); don't re-decide them. **Risky** slices (storage, concurrency) get the full evidence: environment, sensitivity check, limitations. Reviewers read the plan's **Accepted risks** (numbered "AR n" below) before reporting P0/P1. `[P]`: the file list overlaps no slice that can run at the same time. Evidence goes in `evidence/txxx-<topic>.md`. One user story, so every task after setup is `[US1]`.

Locks and tokens follow research §3 exactly: one registry lock; every service call receives the job's token and is not wrapped in a lock (AR 10); `Complete` checks the token and saves inside the registry lock; completion never takes the sign-in lock (AR 9); jobs never use `RequestAborted`.
